# Muras Bot (history-bot)

Ежедневный Telegram-бот, который публикует короткий исторический факт: находит статью в Wikipedia или экспонат в Smithsonian Open Access, перерабатывает её через Gemini API в лаконичный пост и отправляет в канал.

## Как это работает

Канал — в первую очередь про историю. Каждый запуск бот выбирает один из трёх типов контента (веса в `src/pick.js`):

- **Регион + тема (~75%)** — берёт случайную пару из списка регионов (Кыргызстан, Центральная Азия, СНГ, Запад, Азия, Латинская Америка, Африка) и тем-«линз» (политика, география, экономика, культура, социология, антропология, философия, идеология, причины и последствия), ищет непоказанную статью в Wikipedia и просит Gemini выбрать самую интересную из кандидатов и переписать её в формате поста. Для темы «География» используются отдельные запросы регионов (`geoTerms`: горы, реки, моря, города, границы). Если у статьи нет главной картинки, бот берёт первое изображение из её текста.
- **Музейный экспонат (~20%)** — то же самое, но источник — Smithsonian Open Access (по англоязычным поисковым запросам для региона).
- **История + поп-культура (~5%, не два дня подряд)** — обычный исторический пост по статье Wikipedia, в котором Gemini перекидывает мостик к известному фильму/книге/комиксу/игре, документально основанному на теме статьи. Заранее заданного списка произведений нет; если надёжной связи нет, публикуется обычный исторический пост.

Углы подачи (развенчание мифов, происхождение названий и границ, роль географии, сравнения масштабов) частично вдохновлены civixplorer.com. Если основной выбор ничего не находит, бот пробует обычный исторический пост ещё раз.

История хранится в `data/shown.json` и коммитится обратно в репозиторий после каждого запуска. Статьи Wikipedia учитываются по разделам: каждый пост берёт ещё не показанный раздел, поэтому большие темы («Киргизская ССР») могут возвращаться много раз, а в `shownTitles` статья попадает навсегда только когда все её разделы исчерпаны. Последние 30 статей (`recentTitles`) временно не повторяются.

## Структура проекта

```
index.js            — точка входа, оркестрация трёх сценариев публикации
src/config.js        — регионы (с поисковыми запросами) и темы
src/pick.js          — логика взвешенного случайного выбора
src/wikipedia.js      — поиск непоказанной статьи в Wikipedia
src/smithsonian.js    — поиск непоказанного экспоната в Smithsonian Open Access
src/claude.js         — обращения к Gemini API (переписывание факта, отсылки к поп-культуре, выбор лучшего кандидата)
src/telegram.js       — отправка сообщения/фото в Telegram
src/history.js        — чтение/запись data/shown.json
src/http.js           — обёртка fetch с ретраями и таймаутами
data/shown.json       — история: исчерпанные статьи, показанные разделы, недавние темы
.github/workflows/daily.yml — GitHub Actions: ежедневный запуск по cron
```

## Настройка

### Переменные окружения

| Переменная | Обязательна | Описание |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | да | Токен Telegram-бота |
| `TELEGRAM_CHAT_ID` | да | ID канала/чата, куда публикуются посты |
| `GEMINI_API_KEY` | да | Ключ Gemini API для генерации текста |
| `SMITHSONIAN_API_KEY` | нет | Ключ Smithsonian Open Access API (нужен для сценария с музейными экспонатами) |

### Локальный запуск

```bash
npm install
TELEGRAM_BOT_TOKEN=... TELEGRAM_CHAT_ID=... GEMINI_API_KEY=... node index.js
```

Требуется Node.js 20+.

### Автоматический запуск

Бот запускается ежедневно через GitHub Actions (`.github/workflows/daily.yml`, `cron: "0 1 * * *"`, можно запустить вручную через `workflow_dispatch`). Секреты (`TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`, `GEMINI_API_KEY`, `SMITHSONIAN_API_KEY`) должны быть заданы в настройках репозитория (Settings → Secrets and variables → Actions). После каждого запуска workflow коммитит обновлённый `data/shown.json` обратно в ветку.
