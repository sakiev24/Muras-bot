# Muras Bot (history-bot)

Ежедневный Telegram-бот, который публикует короткий исторический факт: находит статью в Wikipedia или экспонат в Smithsonian Open Access, перерабатывает её через Gemini API в лаконичный пост и отправляет в канал.

## Как это работает

Каждый запуск бот выбирает один из трёх типов контента:

- **Регион + тема** — берёт случайную пару из списка регионов (Кыргызстан, Центральная Азия, СНГ, Запад, Азия, Латинская Америка, Африка) и тем (политика, экономика, общество, культура, повседневная жизнь, идеи, причины и последствия, философия), ищет непоказанную статью в Wikipedia и просит Gemini выбрать самую интересную из кандидатов и переписать её в формате поста.
- **Музейный экспонат** — то же самое, но источник — Smithsonian Open Access (по англоязычным поисковым запросам для региона).
- **Поп-культура и история** — фиксированный список фильмов/сериалов/игр/музыки с исторической подоплёкой; Gemini генерирует факт напрямую, без Wikipedia-статьи. Каждая тема помечена `verified: true/false` — правда это задокументированный факт или распространённая интерпретация.

Регионы и типы контента выбираются с весами (см. `src/config.js`), чтобы не показывать одно и то же слишком часто. Если основной выбор ничего не находит, бот подстраховывается постом из поп-культуры.

История уже показанных заголовков хранится в `data/shown.json` и коммитится обратно в репозиторий после каждого запуска, чтобы не повторяться.

## Структура проекта

```
index.js            — точка входа, оркестрация трёх сценариев публикации
src/config.js        — регионы, темы, список поп-культурных тем
src/pick.js          — логика взвешенного случайного выбора
src/wikipedia.js      — поиск непоказанной статьи в Wikipedia
src/smithsonian.js    — поиск непоказанного экспоната в Smithsonian Open Access
src/claude.js         — обращения к Gemini API (переписывание факта, выбор лучшего кандидата)
src/telegram.js       — отправка сообщения/фото в Telegram
src/history.js        — чтение/запись data/shown.json
src/http.js           — обёртка fetch с ретраями и таймаутами
data/shown.json       — история уже опубликованных заголовков
.github/workflows/daily.yml — GitHub Actions: ежедневный запуск по cron
```

## Настройка

### Переменные окружения

| Переменная | Обязательна | Описание |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | да | Токен Telegram-бота |
| `TELEGRAM_CHAT_ID` | да | ID канала/чата, куда публикуются посты |
| `GEMINI_API_KEY` | да | Ключ Gemini API для генерации текста |
| `SMITHSONIAN_API_KEY` | нет | Ключ Smithsonian Open Access API (нужен для сценария с музейными экспонатами) |

### Локальный запуск

```bash
npm install
TELEGRAM_BOT_TOKEN=... TELEGRAM_CHAT_ID=... GEMINI_API_KEY=... node index.js
```

Требуется Node.js 20+.

### Автоматический запуск

Бот запускается ежедневно через GitHub Actions (`.github/workflows/daily.yml`, `cron: "0 1 * * *"`, можно запустить вручную через `workflow_dispatch`). Секреты (`TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`, `GEMINI_API_KEY`, `SMITHSONIAN_API_KEY`) должны быть заданы в настройках репозитория (Settings → Secrets and variables → Actions). После каждого запуска workflow коммитит обновлённый `data/shown.json` обратно в ветку.
